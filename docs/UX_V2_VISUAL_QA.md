## 实际发现并修复

1. 改版前首页和360概览的compact图实际抛出JavaScript `TypeError: Cannot create property 'bottom' on number '5'`。原493项测试没有检出该前端问题。改成四边padding对象，并增加回归测试；当前图实际显示。
2. 演示角色切换收进popover后，跨页重新打开会将前端选中项初始化成首项，与保存角色不同步。显式同步初始索引后，实际从成员历程→健管→医生→管理员→成员均成功。
3. 首轮全量回归501通过、1失败，是旧测试检查角色列表的源代码字面格式；改为检查新角色映射及统一样式文件，未放宽业务断言。
4. 图表和任务详情过长的初稿经过截图复查：比较表移到图下展开；医生背景移到相关趋势后；集成说明进入就地详情；完整历程保留但默认收起较早事件。

## 可用性与可访问性

- 成员“首页→去完成→确认完成”沿用原TaskTransitionService。浏览器验证进入目标任务；实际写入由原业务/UI回归覆盖，截图库不提交示范操作。
- 健管事项选择改变右侧处理上下文，原处理按钮与路径仍保留。计划/随访/阶段结果快捷入口由AppTest实际打开表单。医生与健管共用工作区，医生提交责任边界不变。
- 核心导航Member5、Manager5、Admin4；详情页签保留上下文。常用操作从相应导航/成员上下文最多3次激活可到达；完整表单填写不按一次点击计数，低频技术诊断不承诺3次。
- 悬停当前体重点实际显示日期2026/09/01、85.8、kg、当前、来源健康数据；没有UUID。这里只验证演示数据，不推断医学改善。
- 键盘从主按钮Tab至原因展开项，实际焦点轮廓3px；原生按钮/单选控件可键盘操作。状态同时有文字，不只靠色彩。
- 正文/辅助文字采用深灰蓝；浏览器检查caption计算颜色为`#52677D`、字号12.96px；正式轴13px，实体轴线保留。
- 窄屏实测主区域clientWidth=640、scrollWidth=640。不是全设备/读屏器认证；工作人员以桌面为主。

## 保留与边界

94个业务要素组均有新路径；1,215个底层调用点作为历史快照，不等同独立测试数量。所有原UI函数保留，15个高级兼容renderer逐项AppTest运行。原报告、基线、风险、医生、计划/任务、服务、阶段结果、时间轴、Agent、知识、设备、AI、反馈、规则和审计入口均保留。

没有修改Model、Migration、业务Service、Risk规则、Baseline冻结逻辑、医生责任、Agent自主性或Timeline事实来源。新增照护团队投影只读现有计划/复核/服务记录，不伪造团队成员。演示角色仍非登录鉴权。

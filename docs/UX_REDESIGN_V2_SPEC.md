# HealthOps UX V2 — implementation specification

设计冻结点：2026-09-19，研究与现状盘点后、产品代码修改前。基于 `62d9ae3`。

## 新信息架构

Member：**首页 / 健康 / 计划 / 服务 / 历程**。健康内：概览、数据、体检、医疗档案。个人设置保留资料、设备与数据、授权。

Manager：**今日 / 成员 / 医疗协同 / 服务 / 更多**。成员360保留概览、健康、管理、医疗、历程；管理操作是页内任务选择，不增加路由。医疗保留内部医生及外部协作；更多保留专业资料与系统入口。

Doctor：**待我复核**工作台，页内切换待复核/已完成，左队列与背景依据、右判断及执行交接。

Admin：**集成与数据 / 自动化运营 / 规则与知识 / 系统状态**。系统状态下高级信息容纳治理、审计及历史兼容工具；不删除能力。

## 布局与线框

### Member 首页（A+B）

```text
[今日健康 · 成员姓名]                  [个人设置]
┌ 今天最重要的事情 ──────────────────┬ 负责你的团队 ┐
│ 真实任务标题 / 截止 / [去完成]        │ 健管 / 医生  │
│ 查看原因（展开完整原文）              │ 服务协调人   │
└───────────────────────────────────┴────────────┘
[当前周期 · 阶段 · 下一服务]  [管理进展详情]
[近期变化：体重趋势]       [血压趋势]
[其他今日行动 / 查看计划 / 上传报告 / 健康数据]
```

只对主任务加强权重，其他原有动作仍在“其他今日行动/常用入口”。负责人来自既有记录，无数据时明确待确认。

### 健康（图表优先）

```text
[健康] [概览 | 数据 | 体检 | 医疗档案]
[2026年度健康基线 · 已确认 · 记录日期]
[指标选择]                         [时间范围]
[当前值 / 基线值 / 数值方向]
[完整主趋势图：轴 / 单位 / 基线 / 当前]
[展开所有指标对比与相对变化]
[查看年度基线] [持续关注事项]
[重要健康背景与完整依据（展开）]
```

现有轴 helper、320px图高、深色轴与标注保留。完整比较表移到图下折叠区，不删除。数据详情保持同一投影，含睡眠/活动/血压与来源。体检最近结果和历史趋势保留。

### 计划 / 服务 / 历程

计划：目标与负责人摘要→执行进度→任务分类与完成→近期节点→阶段结果；方案选择仍可展开。

服务：默认当前申请；状态路径与下一步→安排/结果详情；可用服务和历史保留同层切换，申请/取消沿用服务。

历程：按日期的事件轨道，类型与摘要同列；完整时间轴、筛选与证据仍在下方展开，不新增事实表。

### Manager 今日（B+C）

```text
[今日待处理] [待处理 | 即将逾期 | 等待医生 | 等待成员 | 高优先级]
[类型筛选] [查找成员/事项]
┌ 工作列表 5/12 ───────────┬ 选中事项 7/12 ───────────────┐
│ 成员 · 类型              │ 问题 / 状态 / 截止 / 负责人   │
│ 标题 · 状态 · 截止        │ 为什么 / 下一步              │
│ [选择事项]               │ [处理] → 原有上下文处理入口  │
│ ……分页，全部事项可达      │ 关联健康摘要 / 原始详情展开    │
└────────────────────────┴─────────────────────────────┘
[自动跟进状态（展开）]
```

列表不出现长段正文；全文在选中面板保留。不改变去重、风险优先级和工作项来源。分页只改变显示，不截断数据。选中后处理和原工作入口连通。

### 成员360

标题摘要为稳定上下文：成员、周期、负责人、阶段、关注、下一步。
概览：左趋势，右当前管理与服务；完整基线摘要折叠。健康页完整图；管理页上方进展摘要，任务/计划/随访/结果不跨成员上下文。快捷动作可直达指定管理表单，保存写入仍调用原 Service。

### Doctor

```text
[待我复核] [待复核数量 / 已完成]
[待复核 | 已完成] [选择复核事项]
[需要医生判断的问题 · 提交时间 · 接手状态]
┌ 临床上下文 7/12 ─────────────┬ 人工判断 5/12 ──────────┐
│ 关键指标 / 相关趋势 / 用药    │ 医生结论表单            │
│ 依据完整性 / 原文             │ 后续执行说明 / 日期      │
│ 背景 / 已采取行动（展开）     │ [提交判断并交回健管]     │
└────────────────────────────┴─────────────────────────┘
```

已完成/只读视图保留真实分支；不得出现待分配医生矛盾状态。不改变医疗权限边界。

### Admin

连接概况摘要在顶部，左集成清单（名称/状态/最近本会话测试），右所选集成操作。自动化保留全部暂停/恢复/取消/Trace；列表与详情按主次排列。高级兼容工具默认折叠，明确演示管理用途。

## 视觉系统

- 原创医疗蓝 `#185DA8`，文字深灰蓝 `#20354C`，正文 `#334155`，辅助文字 `#52677D`，背景 `#F4F7FA`，内容白。正式风险独占红黄绿灰。
- 12列概念网格：Member 8+4、趋势6+6；Staff5+7、Doctor7+5。窄屏顺序堆叠。
- 标题30px、节标题20px、项标题16px、正文15px、meta13px。正式轴13px保持不变。
- 间距8/12/16/24/32；圆角12；边线1px；无需装饰大阴影、渐变或玻璃。
- section band用于行动/背景分层；列表用行分隔，不每行一个卡片。
- 一页一个主CTA；完成/提交为primary，切换、详情为secondary，撤销保留文字明确的危险动作。
- Material Symbols（Streamlit支持的图标）用于统一少量辅助图标，无emoji装饰。
- 键盘焦点明确，按钮不小于40px，状态带文字，任何临床状态不单靠颜色。
- 统一CSS仅在 `ui/styles.py`；共享 `components.py` 和既有 `experience.py` helpers。

## 安全与保留约束

不改Model、Migration、Risk、Baseline事实、Agent自主性、Timeline投影服务。新ViewModel只读。UI中的所有写入沿用原函数/Service。成员普通页面无UUID/内部枚举/技术Trace。所有原始字段与完整说明移入原详情或高级信息，不删除。

保留映射和静态元素快照见 `UX_ELEMENT_PRESERVATION_MAP.md` 及伴随JSON。组件替换按语义保留，不以保持相同HTML作为验收条件。

## 验收

16个基准页面截图（含所需14页及健管医疗/服务）。同一演示库、同一视口保存before/after。检查图表JS异常而不只Python异常。窄屏检查首页/健康；键盘检查；重点CTA真实操作及全量pytest。每页记录第一眼/主动作/次要信息/视觉锚点/滚动距离。

## 实现中的验收修订

- 演示角色切换进入独立popover，业务导航保留最多5项；当前角色仍在侧栏明示，不声称是真实身份认证。跨页后popover重新挂载时，初始选中项与保存的角色同步。
- 历程默认显示6条重要事件，其余原有20条摘要进入“更多重要事件”，原完整历程、筛选和依据仍可展开。
- 基线完整比较表、百分比与说明保留在趋势下方；没有可绘图指标时仍显示比较入口，不能提前返回导致数据消失。
- 发现原compact图把padding传成数字，当前Streamlit前端尝试写入padding.bottom报错；改成具名四边padding对象。正式图轴、单位、基线和当前注释保留。
- 所有历史详细renderer保留，额外提供15个高级兼容入口。没有将健康业务搬进管理员作为唯一入口；这里补的是原有详细/技术视图。

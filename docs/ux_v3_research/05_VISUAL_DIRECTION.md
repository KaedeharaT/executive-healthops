# UX V3 · Visual Direction（设计标准，不是代码修改）

应用 frontend-design 的目的/气质/差异化方法，ui-ux-pro-max 的可用性清单，frontend-ui-standards 的 token/组件/布局分离规则。HealthOps 的区别是“年度参考点 + 当前变化 + 明确交接责任”，不是一种新卡片外观。

## 三种方向

|方向|体验|布局和视觉锚点|风险及限制|
|---|---|---|---|
|A Consumer health|亲和、行动优先；学习 Included Health/Omada/One Medical 的任务入口|较窄行宽，一个有短原因的主行动；小趋势辅助，负责人可见|不照搬渐变/品牌色、图片卡片或聊天首页|
|B Clinical record|稳健、可信；学习 MyChart 的记录组织|时间、数值、单位和来源稳定对齐；摘要先于详细记录|不把数据库字段平铺，不以蓝色文字替代清晰层级|
|C Care operations|紧凑、高效率；学习 Health Cloud、Linear、HubSpot 的上下文处理|短队列 + 选中详情，状态/负责人/截止在同一上下文|不照搬 CRM 复杂多栏、开发工具快捷键门槛或多层树|

最终配比：Member **A60% + B40%**；Manager **C65% + B35%**；Doctor **B70% + C30%**；Admin **C80% + B20%**。配比描述阅读节奏，不是复制竞品像素。

## Tokens 与组件度量

|项目|冻结建议|验证方法（实现后执行）|
|---|---|---|
|Brand|沿用医疗蓝 `#185DA8`；正文 `#20354C`；次级文字 `#52677D`；白/微灰 `#F4F7FA`|常规文字对比度≥4.5:1；大字≥3:1；不能把低对比 caption 放在关键责任/截止上|
|Risk|正式绿/黄/红/灰仅表达已存在的规则风险；配中文状态|数值↑↓用蓝灰，不自动等于改善/恶化|
|Typography|中文优先：思源黑体/Noto Sans SC，系统中文字体回退；不新增字体加载依赖作为本轮工作|标题28/32，区标题20/24，条目16/20，正文16，meta14，图轴12/标题13；数值等宽数字|
|Spacing|4/8基数：8、12、16、24、32、48；组件内16，段间24/32|不能用单页负margin补布局，长中文不能靠截断保整齐|
|Component metrics|圆角8～12；边线1；主按钮44高；按钮间隔8；非紧急页面主CTA1|同一组件只有角色密度变体，禁止复制样式再微调|
|Page layout metrics|Member内容约960～1120；Staff约1280～1440；12列概念网格，队列4/详情8|1366×768核对问题、负责人、主动作；不要求整份医生依据塞进一屏|
|Focus/keyboard|焦点清晰2px以上；可见标签；DOM阅读顺序与视觉一致|Tab可到筛选/列表/详情/提交；不能依赖hover才出现唯一入口；焦点不被固定头遮挡|

设计方向不改变当前 CSS；实际字体可用性、焦点和对比度需实现时测量，本文不伪称已 PASS。

## 组件与页面节奏

- Page shell → 紧凑摘要 → 主行动/主图/工作区 → 有名称的详细资料 → 次级/高级信息。
- Section 用标题、间距和浅底分区。Card 只聚合属于同一决策的内容；普通工作/记录用列表分隔线。
- List 左侧标题最多两行，必要身份/截止不可省略；长摘要进入详情。选中行与hover不同，状态同时有文字。
- Button 主操作实心蓝，次操作描边/文字；每页默认1个主CTA、2～3个次级导航动作。筛选/展开是控件，不伪装CTA；仍限制控件数量，不通过“文字链接”绕过预算。
- Care team 用角色+实际姓名+当前责任，不造头像、在线状态或即时聊天。无医生分配则写明待分配，不虚构具体医生。
- Evidence 区首行明确“完整依据 / 部分依据 / 暂无原始依据”，给日期和来源。完整原文按需展开；不能只给绿色勾。
- Progress 表示任务/服务阶段进度，不表示治疗效果。阶段结果必须显示日期、所属计划、观察变化与下一决定。

## 图表合同（不能退化）

正式健康图：高度约300px；深灰蓝轴线、刻度和12px标签；X日期、Y数值及单位；浅grid；年度基线带文字虚线，当前点带标签。Y围绕真实数据留白，不强制0；不同单位不混轴；血压双线保留中文图例。

默认当前管理周期；可选7天/30天/3个月/6个月/1年/全部（现有范围能力沿用）。Tooltip：日期/数值/单位/来源类别；详细记录作为可访问替代。0点给补资料路径，1点给真实值且明确不足成趋势；不得做假连线。主页面1张，医生最多2张相关图；首页最多2张小趋势并共用“查看健康变化”入口。

保留现有范围图、报告比较、睡眠分期、活动、干预前后比较和时间轴趋势功能；不适合核心页的图在相应详情或兼容工具中，不删 renderer。

## 窄屏与复杂状态

Member：单列，行动→管理状态/负责人→趋势→安排；不先把桌面侧栏变成长列表。两个趋势可纵排，轴不能隐藏；320/390/640宽及200%缩放作为后续验收。

Staff：桌面优先；窄屏先队列、选中后详情，返回保留筛选/位置，不能左右独立长滚动。Doctor 始终问题→依据→表单；Admin 先状态再展开配置。

所有页：加载保留标题/上下文；失败明确可重试且不假报成功；空队列区别于加载失败；无权限保持角色边界；按钮提交中防重复。避免动效依赖，尊重减少动态效果设置。

## Standards 最终复核

三种方向共用 token；page width 与 component spacing 分离；不新增局部CSS特例；共享状态/负责人/下一步表达；每个图保留轴与单位；不复制品牌/字体资产/图片/截图进产品。设计符合上述约束；浏览器、键盘、响应式与真实业务写入验收留到用户批准后的实现阶段。

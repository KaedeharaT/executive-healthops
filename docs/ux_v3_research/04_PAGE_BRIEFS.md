# UX V3 · Six Page Briefs & Wireframes

**仅六张设计原型；不是可运行UI。** 本稿从角色任务重新组织，不沿旧截图补卡片。尖括号字段是现有事实占位；图中数值只为解释轴结构，不写入应用/数据库。业务动作沿用现有服务，不新增聊天、测量设备、自动诊断或消息发送能力。

## 全页预算与交互规则

|页|默认主要Section|主CTA|次CTA|核心图|视觉锚点|
|---|---:|---:|---:|---:|---|
|P1 Member Home|4|1|3|2个预览|当前最重要行动|
|P2 Member Health|4|1|3|1|基线→当前与主趋势|
|P3 Manager Today|3|1|2|0|短队列与选中事项|
|P4 Member360|5（含紧凑抬头）|1|3|1|成员上下文与下一步|
|P5 Doctor Review|4|1|2|1（必要时最多2）|医学问题与依据完整性|
|P6 Admin System|4|1|3|0|真实运行状态与需处理异常|

全局导航、选项筛选、折叠控件不算CTA，但不能无限增加：主内容最多一行上下文选择器，每次只开当前选中详情。表单“提交”成为该状态唯一主CTA，不能和页面“进入处理”同时争主操作。每页默认内容不是无限卡片；列表用行、分隔和对齐组织。

## P1 · Member Home

- **User / question**：成员；今天我应该做什么？
- **Entry / first decision**：角色首页/现有任务直达；判断当前任务由我执行还是等待团队。
- **Primary action**：`去完成`，进入同一任务的现有完成流程；无任务时不硬造任务。
- **Success**：任务完成后有明确回执，下一步负责人可见；不把执行完成说成健康改善。
- **Information priority**：当前行动 → 管理阶段/负责人/节点 → 最近变化 → 近期安排及团队。
- **Primary content**：一个任务、截止、简短原因；一个周期摘要；两条有数据的趋势。
- **Secondary content**：查看原因、查看健康变化、查看安排；其余任务去计划。
- **Hidden detail**：全部任务、完整报告、自动跟进细节、服务历史、完整趋势来源。
- **Recovery**：任务被其他页面处理后刷新并保留回执；任务不可自行完成时说明由谁确认，不显示假成功；不引入新联系渠道。
- **Empty state**：无任务写“目前无需你操作，下一步由〈负责人〉跟进”；无负责人写“待分配”；不足趋势只给一句说明，不留空图。
- **Visual anchor**：一条带明确动作的任务横区，不是六个功能卡。

```text
+------------------------------------------------------------------+

| <成员>，今天先处理这一件事                                        |

|------------------------------------------------------------------|
| 当前管理：<年度/阶段> · <状态>                                    |
| 负责人：<健管>                  下一节点：<真实安排或待安排>       |
|------------------------------------------------------------------|
| 最近变化                                   查看健康变化 >        |
| <体重：当前/变化/单位>       <血压：当前/变化/单位>                |
|   小趋势  ──●──●──●           小趋势  ─●──●──●                    |
|   <时间区间>                  <时间区间>                          |
|------------------------------------------------------------------|

```

**窄屏**：行动、阶段/负责人保持在趋势前；两预览纵排并保留一个共同下钻动作。团队不是从桌面右侧机械移到很远页尾。

**路径**：首页 → 去完成 → 原任务确认。依据 MEM-001～007、V2-001。主任务选择沿用既有业务优先级，不由AI发明推荐。

## P2 · Member Health

- **User / question**：成员；我的健康现在怎么样，和年度起点有什么变化？
- **Entry / first decision**：健康/首页变化入口；先理解年度基线是否已确认与当前数据日期。
- **Primary action**：`查看年度基线`，进入现有基线详情；任务处理留在计划。
- **Success**：可读出基线值、当前值、数值方向、时间和单位；知道变化不自动等于医学结论。
- **Information priority**：年度基线→当前记录日期与比较→主趋势→当前关注→具名档案入口。
- **Primary content**：一条摘要、紧凑比较和一张指标趋势。
- **Secondary content**：健康数据/体检与检查/健康档案；资料覆盖留在基线摘要的一行，完整依据进入详情。
- **Hidden detail**：全指标表、原始记录、报告列表、完整用药病史、修订历史、参考范围图。
- **Recovery**：不兼容单位不计算delta；当前资料未更新明确日期；加载失败不显示“正常”；缺确认基线显示待确认与责任人。
- **Empty state**：无基线引导现有报告上传/人工确认；一条数据显示真实值和“后续数据不足”，不绘制假趋势。
- **Visual anchor**：占主要阅读位置的正式趋势，不把坐标轴换成装饰。

```text
+------------------------------------------------------------------+

| <其他关键指标紧凑行，不展开六张大图>                             |
|------------------------------------------------------------------|
| 从基线到现在       [体重 v]          [当前管理周期 v]             |
| kg                                                               |
| 92 |                                                             |
| 90 | ● - - - - - - - - - - - 年度基线 <值/单位>                |
| 88 |      ●                                                      |

|       1月          3月          6月          9月                  |

|------------------------------------------------------------------|
```

图轴数字为结构示意；最终使用既有图表投影值。血压选项用双线及mmHg，百分比指标delta可用百分点，不擅自作医学好坏判断。四区预算：基线/比较、趋势、关注、详细资料；表头不另算卡片。

**窄屏**：比较表允许按指标纵向重排；主图左/下padding不裁轴，不因手机隐藏轴。依据 MEM-008～019、V2-003。

## P3 · Manager Today

- **User / question**：健管；今天谁最需要处理，为什么，什么时候，下一步？
- **Entry / first decision**：今日或待办直达；从到期/优先级/等待责任选事项。
- **Primary action**：右侧`处理此事项`，进入现有命令表单，不另造快捷写入逻辑。
- **Success**：状态变化有回执，工作有责任人/后续节点，返回队列保留选择。
- **Information priority**：需要本人处理与逾期 → 短列表 → 选中事项原因/关键数据/依据/下一步。
- **Primary content**：5个有行动意义的数字组成一条状态带；主从工作区。
- **Secondary content**：查看依据、打开成员360；类型归筛选，不占一级入口。
- **Hidden detail**：全文摘要、完整历史、自动化技术信息；其余工作仍可翻页/展开。
- **Recovery**：筛选无结果可清除；记录已更新需刷新不重复提交；未指定负责人明确待分配，不能用角色名假装已分派。
- **Empty state**：区分全部处理完、筛选无结果、数据加载失败；三者不同反馈。
- **Visual anchor**：一条被选中短行对应唯一处理面板。

```text
+------------------------------------------------------------------+
| 今日待处理                                                      |
| 需我处理 <n> | 已逾期 <n> | 等医生 <n> | 等成员 <n> | 高优先 <n> |
| [全部类型 v] [状态 v]                         [查找成员/事项]     |
|------------------------------------------------------------------|
| 工作队列（4列宽）             | 选中事项（8列宽）                |
| 成员 / 问题 / 优先 / 截止 / 状态| <成员> · <本次需要处理的问题>  |
| > <成员A> <复查> 高 今天 待处理| 为什么：<短原因>                 |
|   <成员B> <报告> 中 明天 待核对| 关键数据：<值/变化/日期>         |
|   <成员C> <服务> 中 周五 等安排| 依据：<来源/完整性> 查看依据 >  |
|   <更多行，标题不放长摘要>     | > 之前动作（收起）               |
|                               |                                  |
|                               | 状态 <状态> 负责人 <姓名/待分配>|
|                               | 截止 <日期>                      |
|                               | 下一步：<明确业务动作>           |
|                               | [处理此事项 · 主]               |
|                               | 打开成员360 >                    |
|------------------------------------------------------------------|
| 处理回执区域：<保存后更新状态/交给谁/下个时间>                    |
+------------------------------------------------------------------+
默认隐藏：业务全文、全量历史、技术追踪；完整队列仍可到达。
```

三主要区：行动摘要/过滤、工作区、处理反馈（未操作时不留大空框）。详情不和列表同时长滚动。工作列表并不新设指标算法；“需我处理”和“今天到期”标签必须匹配已有投影真实范围，不能沿用误导名称。

**窄屏**：选中后进入详情视图，返回恢复队列；不让用户横向读两栏。依据 MGR-001～006、V2-004。

## P4 · Manager Member360

- **User / question**：健管；管理这个人需要知道什么，以及当前该推进什么？
- **Entry / first decision**：成员列表/今日选中事项；先确认人、周期、主要依赖与下一步。
- **Primary action**：抬头的`处理下一步`，指向当前已有事项；不固定让每个成员都新建计划。
- **Success**：可在同一成员上下文找健康事实、管理动作、医生依赖和结果，无需跨技术控制台。
- **Information priority**：紧凑身份周期与责任 → 基线当前及趋势 → 开放事项 → 当前计划/服务 → 近期事件。
- **Primary content**：一张趋势、最多3个开放事项、当前安排摘要、最多3条近期事件。
- **Secondary content**：查看报告、调整计划、完整历程；详情视图承接其余资料与表单。
- **Hidden detail**：所有任务/服务、详细医疗史、全报告、原始数据、完整时间轴、自动跟进诊断。
- **Recovery**：切tab保留成员；无基线先补资料；没计划显示现有建立入口；无下一步不能编造。
- **Empty state**：缺失资料就给其责任与已有入口，不堆零值卡。
- **Visual anchor**：固定的成员与责任上下文；图表和开放依赖同时可读。

```text
+------------------------------------------------------------------+
| <成员> · <年度周期> · <阶段> · 更新 <日期>                        |
| 负责人 <健管>   主要关注 <短语>                [处理下一步·主]   |
| 下一步：<当前事项或待明确>                                       |
| 概览 | 健康 | 管理 | 医疗 | 历程                                |
|------------------------------------------------------------------|
| 健康摘要 / 近期趋势                 | 开放事项（最多3条）        |
| 年度基线 <已确认/日期>              | <问题> 等医生 <负责人>     |
| <选中指标> 起点→当前 / 数值变化     | <任务> 今天截止 <负责人>   |
| 单位                               | <服务> 待安排 <负责人>     |
| 数值 | ●──●                        | 选中后到同一处理详情       |
|      |      ●──● 当前              |                            |
|      +------------- 时间           |                            |
|        <可读日期刻度>              |                            |
| 查看报告 >                         |                            |
|------------------------------------------------------------------|
| 当前安排                                       调整计划 >       |
| 计划 <目标/进度/下个节点> · 服务 <状态/执行责任/下一步>           |
|------------------------------------------------------------------|
| 近期记录                                       完整历程 >       |
| <日期>  医生判断 → <谁执行>                                      |
| <日期>  服务完成 → <结果归属>                                    |

详细数据进健康；计划/随访/结果表单进管理；医生问题进医疗。
```

五区包含抬头、健康趋势、开放事项、当前安排、近期记录。概览只投影，不复制计划/服务编辑源。健康详情仍保留当前正式轴线、基线参考、当前标记。

**窄屏**：抬头/下一步 → 开放事项 → 趋势 → 安排 → 近期记录，业务优先而不是列顺序机械堆叠。依据 MGR-007～028。

## P5 · Doctor Review

- **User / question**：医生；需要判断什么，证据够不够，判断后交给谁？
- **Entry / first decision**：待我复核→选中问题；确认问题及为何此时提出。
- **Primary action**：`提交判断并交回健管`，沿用现有人工意见/执行说明/跟进日期表单。
- **Success**：医生结论与后续执行责任均保存，返回同源待办；已完成记录只读。
- **Information priority**：问题 → 关键背景和相关趋势 → 依据及用药/既有行动 → 判断/交接。
- **Primary content**：本次问题、1张相关图、依据完整性、表单。
- **Secondary content**：返回队列、查看原始依据；其他资料按标题折叠。
- **Hidden detail**：完整病史、所有健康指标、完整报告定位、历史行动；运营权益和配置不出现。
- **Recovery**：依据不足明确显示；不能自动代作医学判断；不新增“批准全部”或自动风险修改。退出保留上下文；提交失败说明未保存，输入保留的技术实现另行验收。
- **Empty state**：无待复核回队列正常空状态；无趋势显示缺少后续值，保留问题和来源；无原始依据不能写完整。
- **Visual anchor**：问题和证据标签，而非一个巨大结论输入框。

```text
+------------------------------------------------------------------+
| < 返回待我复核                        <成员> · <提交日期/状态>  |
| 需要你判断                                                      |
| <本次明确医学问题>                                               |
| 为什么现在：<触发背景，不是AI诊断>                               |
|------------------------------------------------------------------|
| 关键背景：<相关问题/年度参考/必要医学背景>                        |
| 相关趋势 [血压 v] [30天 v]                                      |
| mmHg | ●──●──●  收缩压                                         |
|      | ○──○──○  舒张压                                         |
|      +--------------------------- 时间                           |
|        <日期刻度>     <数值/单位/来源可核对>                     |
|------------------------------------------------------------------|
| 依据：<完整 / 部分 / 暂无原始依据>          查看原始依据 >       |
| <报告日期/来源/关键片段或具体缺失说明>                           |
| > 当前用药与健康问题（关键安全背景默认摘要，全文展开）            |
| > 已采取行动（收起；与当前问题相关）                            |
|------------------------------------------------------------------|
| 医生判断                                                        |
| <医生姓名/科室>                                                  |
| 人工意见 [....................................................] |
| 交给健管的下一步 [............................................] |
| 建议跟进日期 [日期]                                              |

|                              [提交判断并交回健管 · 主]          |
+------------------------------------------------------------------+
默认隐藏：无关指标、完整历史、定位技术信息；没有运营设置。
```

不靠勾选“我已读”替代证据阅读；表单位于依据之后，允许合理滚动。未分派责任不能写假姓名；既有队列没有独立截止时不捏造SLA倒计时。依据 DOC-001～011。

## P6 · Admin System

- **User / question**：管理员；哪里正常、哪里需处理，先做什么？
- **Entry / first decision**：系统状态首页；区分未配置/未测试/真实失败。
- **Primary action**：`处理选中问题`；无异常则选中配置成为主动作，不做“全正常”假断言。
- **Success**：进入正确已有配置或人工处理入口，结果与高级诊断能核对。
- **Information priority**：运行状态→需处理事项→连接概况→审计/治理/兼容。
- **Primary content**：状态行，不铺四张配置表单；选中才加载对应详情。
- **Secondary content**：检查配置、操作记录、管理工具目录（最多3个）；行选择不是多份等权CTA。
- **Hidden detail**：密钥配置表单、映射规则、Trace、原JSON、反馈评测、旧工具。
- **Recovery**：测试失败不覆盖上次结果含义；无历史结果写未记录，不把会话测试当长期监控；不新增监控采集能力。
- **Empty state**：没有真实设备写明模拟/未验证；没有合作方写未连接；没有异常记录不等于系统健康证明。
- **Visual anchor**：带文字状态的紧凑表及一个选中异常面板。

```text
+------------------------------------------------------------------+
| 系统状态 | 集成与数据 | 自动化运营 | 规则与知识                  |
| 系统运行概况                     <检查时间/无记录明确说明>      |
| 数据访问 <状态>    自动化待处理 <真实数>    当前环境 <演示>       |
|------------------------------------------------------------------|
| 需要处理                                                        |
| <选中问题：发生什么/影响哪个过程/谁负责>                         |
| 下一步：<已有人工处理或配置动作>             [处理选中问题·主]  |
|------------------------------------------------------------------|
| 集成概况（选中一行，再进入该配置）                               |
| 名称          状态                     最近测试/同步            |
| 数据导入      <可用/失败/未验证>        <时间/未记录>            |
| AI服务        <未配置/待测试/可用>      <时间/未记录>            |
| 专业知识      <本地可用/合作方未连接>  <时间/未记录>            |
| 设备          <模拟数量/真实验证数量>  <时间/未记录>            |
|                                             检查配置 >          |
```

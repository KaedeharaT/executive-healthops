# Agent 真实业务进度

## 使用方式

从会员 → Member360 → 健康档案上传资料，健康管理助手顶部直接显示整体百分比、当前步骤、已完成步骤、运行时长。文件信息提取数量单独显示；当前动作旁保留小型医疗蓝 spinner。体检后管理复用原运行看板和同一进度组件。

百分比是业务步骤完成数 / 业务步骤总数，不是模型生成进度、健康评分或预计剩余时间。时间仅影响耗时文字及等待提示，不影响百分比。

## 数据来源与边界

- `services/agent_progress.py` 的 `AgentProgressProjection` 只读查询现有 `AgentPlanStep`、`AgentRunTrace` 及 `AgentGoal` 执行事件，没有第二套状态机。
- 初评 7 步：资料接收、内容读取、健康信息提取、档案匹配、初评预填、健管确认、完成。读取完成由真实 `CONTENT_READ` 事件证明；解析、匹配与确认来自原计划完成记录。档案匹配与预填在原服务同一原子操作完成，两个业务步骤可同时完成。
- 体检后管理 6 步：报告接收、系统分析、责任分流、专业确认、行动建立、完成。专业确认须包含必需的医生关卡；明确无需医生的已跳过记录不会假装成医生已判断。
- 多文件的整体步骤仅在本批每份资料均完成该步后标记完成；文件子进度计数已完成信息提取的文件。因此前两份文件已经整理完、第三份尚在读取时，整体仍停在读取步骤。文件数量不是整体百分比。
- 当前动作单独来自正在处理的文件，不把整批最慢步骤误当成当前文件动作。重试按真实解析开始时间隔离本次 AI 记录，不将上次超时显示为新请求失败。
- 请求开始、结束与超时由现有 `LocalLLMClient` 的调用观察器发布；只保存状态、时间和安全原因类别，不保存提示词、模型回答或隐藏推理。
- 真实请求期间百分比保持不变。30 秒提示“仍在处理中”；90 秒提示“处理时间较长，系统仍在等待结果”。这些阈值不触发失败。
- 真实超时保持原有回退策略：保留可核实规则结果和原文件；无可靠结果由原流程转人工。失败不跳 100%。
- 人工等待没有 spinner；完成后 100%，不自动刷新。活动初评每 2 秒刷新；体检后管理沿用活动 5 秒、医生等待 30 秒的既有刷新策略。
- 为让执行期间也能刷新时间，初评页面将原有有界执行器提交到单线程后台执行。数据库 CAS/租约仍拥有唯一执行权；与原 worker 并发时不会另建 Goal 或重复执行。
- 文件解析、网络/LLM 请求仍在数据库写事务之外；执行事件使用独立短事务。没有新增 Provider、模型配置、Risk 计算或医学事实写入路径。

## 真实 Chromium 验收

环境：Chromium 151.0.7922.34，独立合成数据库 `.runtime/agent-progress/qa.db`，入口 `http://127.0.0.1:18589`。从首页点击会员 → Member360 → 健康档案，没有内部页面 URL 或 session-state 注入。

一次上传：结构化问卷、文字体检报告、自由文本 DOCX 历史档案。

- 实际观察：0% → 14% → 29% → 43% → 71%。
- 本地 AI 实际请求成功，耗时 3626 ms，接受 1 项有原文依据的候选信息。
- AI 运行期间始终 29%，第 3 / 7 步；文件信息提取 2 / 3。
- 健管等待 71%，spinner 停止。
- 通过原例外队列处理剩余项，实际填写 6 项明确未知回答，保留其他可选缺失资料未知；一次确认提交后 100%，3 / 3 文件，无 spinner。
- 知识库未调用，界面明确“本流程未使用”。

超时使用独立 `.runtime/agent-progress/timeout.db` / 18590，原本地 LLM 服务，仅该验收进程将已有 `LOCAL_LLM_TIMEOUT_SECONDS` 设为 1。实际 HTTP 请求触发 `ReadTimeout`，非模拟延迟、非伪造状态。页面停在 29%，2 / 3 文件；AI 耗时 1 秒，spinner 停止，原文件下载、重试与转人工入口均存在。正式环境的超时配置没有改变。

恢复该验收进程原超时配置后，通过页面“重新尝试”继续原实例，实际观察 29% → 43% → 71%，再次进入健管确认。重试截图另存 `timeout/retry/`；该次复核暴露的历史超时提示残留问题随后修复，并加入专项回归断言。

截图与页面文字位于 [images/agent-progress](images/agent-progress)。正常流程 `browser-result.json` 与超时流程 `timeout/browser-result.json` 分别记录实际观察结果。

复现浏览器：先通过现有服务启动器为上述端口准备独立合成会员环境；运行 `scripts/qa_agent_progress.py --upload`，再运行 `--finish`。超时验收设置 `HEALTHOPS_PROGRESS_QA_URL=http://127.0.0.1:18590`。脚本禁止对正式端口执行测试数据写入。

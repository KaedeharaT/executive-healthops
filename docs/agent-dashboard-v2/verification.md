# 健康管理助手责任分流与运行看板 V2

## 真实使用路径

健管在今日工作的健康管理助手卡片点击「查看运行看板」。会员360的「自动跟进」进入同一个实例、同一个看板，返回时保留会员上下文。已完成流程也保留看板入口。

看板显示新报告为何启动流程、已完成工作、当前执行者、责任分流理由、人工记录和下一步。系统发现、现有正式风险、医生判断分别展示。需要医生的报告直接提供「确认并提交医生」，普通管理确认仍保留。行动确认使用全宽表格，完成首屏显示真实数量及下一节点，底部保留完整出口和会员360按钮。

医生仍在「待我判断」提交医学判断，不进入运行看板。管理员使用同一个业务看板，并可展开技术详情；不展示原始载荷、提示词或隐藏推理。

## 责任约束与记录

- 共享 `ResponsibilityRouter` 只决定处理责任，不计算医学风险。
- 自动处理、健管确认、医生判断、优先人工处理均有明确原因代码、摘要、规则/依据引用、时间和确认人。
- 路由通过现有 `AgentRunTrace.metadata_json` 持久化；复用原目标、事件、计划、工具与审批体系，无第二套框架、无重复业务事实表。
- 优先读取现有风险记录的紧急处理/医生复核要求。无法可靠解析、关键数据矛盾、人工接手时停止普通流程。
- 医学责任只能由本会员真实、已确认的医生复核解除；伪造上下文中的医生结果不能解除。
- 模型建议只能增加人工责任，不能降低医生或升级要求。V1 不能使用通用重新规划或旧工具绕过人工关卡。
- 人工重试重新读取真实资料和当前安全规则。未解除的问题继续升级；解除后恢复原人工节点。
- 健管不能通过行动编辑器新增没有医生依据的处方、调药或医学决定。
- 旧实例的责任记录从实际升级时间开始，不补造历史；启动脚本幂等补齐记录。

## 展示的真实性

工作完成标记来自成功的业务工具记录；人工记录来自审批和医生提交记录。运行时长包括真实等待时间，完成后停止计时。知识数量来自已审核检索结果，缺失时不编造依据。无正式新风险时不制造风险；既有风险不会标为本报告新触发。

运行截图来自实际报告重新读取操作，未使用模拟延时。现有 V1 同步事务中的处理状态通过正在执行的业务命令显示，已完成历史来自已保存记录。打开的医生等待看板每30秒检查真实状态，活动状态每5秒检查；进入人工编辑节点后停止定时刷新，避免打断编辑。

## 元素与语义保留

保留原六步有限状态机及数据库阶段，只将单层业务流程展示为：报告接收、系统分析、责任分流、专业确认、行动建立、完成。

报告数值及核对状态、基线、趋势、历史背景、用药、知识依据、报告下载、健管摘要修改、医生提交、行动编辑、最终创建、完成出口及会员自动跟进均保留。健康基线和 Risk Engine 实现未修改。

# 初始健康评估入口验收

## 使用路径

健管进入「会员」，点击会员行，再点「健康档案」。首块固定显示「初始健康评估」。
从会员列表开始：会员行 → 健康档案 → 开始评估，共 3 次业务点击；不再选择会员或问卷。

| 状态 | 页面操作 |
|---|---|
| 未开始 | 开始评估；说明十个资料部分 |
| 填写中 | 继续填写、查看已填写内容；显示已保存部分和保存时间 |
| 待健管确认 | 开始健管确认；今日工作同时出现对应评估事项 |
| 待医生确认 | 保留原有医学确认流程，明确等待对象 |
| 已完成 | 完成时间、健管确认状态、本人关注、专业管理重点；查看评估、补充/修正 |

问卷仍是原有 11 步 Wizard：10 个资料部分及确认提交。当前用药和最近用药仍全部保留。
详情固定显示会员、年度、责任健管和评估状态，并提供返回健康档案。

## 业务复用与安全

- 复用 `IntakeAssessment`、`ManagementWorkflowService` 和 `MemberManagementProjection`。
- 老会员缺少评估记录时，通过幂等业务命令建立同一会员/年度的现有问卷；数据库结构没有新增。
- 健康档案读取同一份 `responses`，未新增病史、用药等第二份事实。
- 提交后进入待健管确认；确认前后均标明会员自述与医学事实的区别。
- 专业管理重点与会员本人关注分开。
- 普通问卷填写、提交和健管确认不生成诊断、正式 Risk 或正式用药。
- 医学问题和补充检查继续使用原有 DoctorReview 门槛。
- 修正使用原有退回补充流程，保留原记录，重新提交和确认。
- 今日工作按评估唯一 ID 打开对应年度；老年度方案缺少 cycle_year 时沿用原有开始年份语义，正确显示责任健管。
- 搜索到的不可操作提示已替换为「去补充初始评估」按钮。

全部原健康档案内容保留；原表格中的初始评估行移至顶部固定入口，没有增加一级导航。

## 浏览器验收

真实 Streamlit + Chromium，从普通健管角色首页通过可见控件进入。
使用现有合成 Demo 数据库的隔离副本，所有问卷写入由真实表单完成，未直接设置业务状态。
原日常演示数据库不受验收填写影响。

场景 A：无评估 → 顶部开始入口 → 同一会员 Wizard。
场景 B：保存基础资料 → 返回档案 → 填写中、1 / 10、继续填写。
场景 C：填写并提交 → 今日工作出现「初始健康评估已提交」 → 直接健管确认。
场景 D：确认 → 今日工作待办消失 → 档案显示已完成、确认时间、关注与专业重点 → 查看原始回答。
另验证已完成后可以补充/修正，沿用同一问卷。

# 目标驱动的长期健康管理闭环

本轮基线：`a321b37a2470e8fbc40f9f41bc336fb13a76b008`。
备份分支：`backup/pre-goal-data-loop`。保留正式 Demo 的原健康数据。

客户目标 → 指标要求 → 已有数据与缺口 → 人确认计划 → 持续数据 → 每日摘要 → 有意义变化 → 相关历史 → Risk Engine → Agent → 必要的人工关卡 → 实际行动 → 新数据。

## 目标与计划

`ManagementGoal` 是现有 `HealthProgram` 的目标定义，与年度方案一对一关联；阶段继续使用 `ProgramPhase`，任务继续使用现有 Task、Followup、Recheck 和 Service 能力，不建立第二套年度管理体系。

初评确认后，从会员关注和既有方案整理目标草稿。明确的“3个月减5kg”可结合实际体重基线得到目标值；没有可靠基线时保持非数值草稿，不能虚构起点。目标类型限于体重、血压、血糖、血脂、睡眠、活动、生活方式、随访、自定义。

持久化 `MANAGEMENT_SETUP` AgentGoal 先等待健管确认目标，再准备有限的业务计划草稿，等待健管确认计划。两次人工决定均产生 HealthEvent，恢复同一个 AgentGoal。计划确认要求已确认年度基线；确认后使用现有阶段和 Tool Registry 的 `create_management_item` 实际建工作，不以“分析完成”代替结果。已有阶段予以复用。

这里的三阶段模板是运营组织方式，不是医学标准。频率沿用既有批准配置，未配置时明确留空，不让模型自行决定检查或治疗频率。医学检查与治疗继续走现有医生责任边界。

## 目标如何决定指标

`services/goal_metrics.py` 保存版本化 Metric Requirement Registry，只引用既有 canonical metric registry。CORE 缺失提示，SUPPORTING 缺失建议下次补充，OPTIONAL 缺失保持安静。每项包含可用来源能力及数据新鲜度窗口。腰围是减重目标的辅助指标，不因缺腰围阻塞整个计划。

资料解析仍只提取实际有依据的内容；确认后的 Observation 自动改变当前目标的数据准备情况。不存在于当前 Observation Registry 的饮食、入睡时间等不能虚构成数值指标；原文和现有结构化事实继续留在资料/沟通记录中。手机与设备的支持能力以已接入适配器为准。

数值进度由 Decimal 确定性计算 `(当前值-基线)/(目标值-基线)`，显示实际值、剩余值及有边界的目标完成百分比。无数值目标不显示虚构百分比，只按阶段及任务表述进展。

## 每日数据和变化

Observation 写入仅合并一个“会员/本地日期”的待聚合标记。现有 worker 每轮按批处理已结束的日期，没有新数据就不重新计算。数值来源是有效 Observation，不是 Raw Device Event，也不调用 LLM。

日累计步数、运动与睡眠时长取最大值，防止累计快照重复相加；体重等状态值取当天最近记录；血压、心率等取均值。摘要记录聚合方法、样本数和证据引用。完整度以目标 CORE 指标为分母，未定义目标时不声称一个完整度百分比。

变化检测比较最近7日、30日，并在相关回溯中读取年度基线。生活方式变化阈值来自已经 APPROVED 的 ManagementRule；正式异常独立复用已批准 RiskRule 的匹配、适用范围与来源限制，不依赖另配生活方式规则。没有已审核阈值，不凭空制定医学异常标准。连续稳定数据不产生变化事件、不唤醒 Agent。已确认数值目标的达到节点可生成进度变化；微小波动不触发此规则。

变化事件的来源键由摘要身份、规则、日期窗口组成，重算摘要不会重复唤醒。同一日期有一个当前摘要，修改产生历史修订。变化后的上下文只包括相关指标、限定天数、关联目标阶段及有限相关记录，不加载全生命周期或无关检验项目。用药上下文仅引用相关医生/沟通记录明确提及的有效用药计划，不推测药物用途。

健康状态变化进入现有 Risk Engine。GREEN/YELLOW/RED 与 AutonomyPolicy、ResponsibilityRouter 保留原逻辑；没有风险规则覆盖不能冒充 GREEN。正常目标进展可记录明确无需额外行动；需核对事实、目标/计划确认、医学判断或高责任动作才叫人。

## 沟通与责任

管理记录使用自然语言输入，保留原文，同时准备结构化摘要及后续安排。写着“和王医生讨论”并不证明医生来源。健管转述必须关联已确认的 DoctorReview，才能成为正式医生意见；健管自己的判断始终标记为管理记录。医疗复查只能沿用明确的已确认医生依据。

## Member360

导航和 Soft Neumorphism 样式保持不变。初评、目标、年度基线、计划未准备好时显示下一步入口，不显示空的阶段0/0工作台，也不提供新增安排。正式管理仍是当前目标、阶段进度、当前行动/开放事项、最近记录四区。概览嵌入目标进展与最近摘要；来源详情放健康档案的展开项；目标/计划确认、变化和沟通进入原有历程。

## 部署与验证

数据库使用增量迁移 `0032_goal_data_loop`。迁移不删除原健康数据、不调用 Demo seed；执行前应备份并在副本验证。Windows 启动脚本不默认迁移或 Rebuild。功能和浏览器流程验收使用隔离数据库，正式 Demo 已使用保留原数据的0032结构启动。

全量回归发现旧 `test_portfolio_builder_rebuild_creates_training_tables` 直接重建默认 Demo 路径的问题。已改为复制构建入口到 pytest 临时项目后验证，正式路径不会再被此测试使用。本轮正式库从测试前保存的完整副本恢复，剔除的只有两位明确的合成浏览器验收会员及依赖记录；74张原有表的既有主键均保留，1522条 Observation 和1434条 Raw 的原字段逐条一致，外键检查为0。恢复核对记录位于本机 `.runtime/goal-formal-recovery.json`，备份位于 `.runtime/backups/pre-goal-data-loop/`。

回归同时复现 Windows 启停注册文件替换时的短暂读锁；读取端增加有界重试，不能把读锁误判为服务已停止。

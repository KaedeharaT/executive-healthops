重复必须同时满足：同一页面/业务上下文、同一最终目标、同一业务副作用、同一 member/item/goal 上下文、同一用户目的。相同文案不是充分条件。

## 路由与 state

合并 **4** 组历史路由/详情路径：

1. 健管 Profile 旧详情 → 当前 Member360 健康档案前置工作区，保留原 G 和返回来源。
2. 管理员 Profile 专用详情 → Operations Board 分派同一个 intake renderer，并传原 G 所属 A；不创建新 Agent。
3. 两套旧更多/系统菜单 → 正式管理员四区，旧 key 只作兼容解析，不再渲染旧目录。
4. 规则与知识中的设备中转 → 数据与集成唯一设备配置。

知识检索/规范 renderer 调用统一不另算第五条路由。不同业务类型的体检六步看板和资料七步看板保留各自真实状态模型；同一个实例没有两套详情实现。

会员列表打开详情前递增表格 epoch，返回时不会因旧选中行立即重开；年度保留原 P 和 origin。旧 `管理事项` state 规范化为 `事项历史`，开放事项仍在上方处理。已选 G 不被默认最新实例覆盖；返回来源明确区分今日、会员、年度。

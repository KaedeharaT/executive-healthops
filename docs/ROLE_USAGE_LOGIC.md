# Role Usage Logic

## Member

核心问题：今天做什么、健康怎么变化、谁负责、下一步是什么。

一级：首页 / 健康 / 计划 / 服务 / 历程。
首页顺序：主行动 → 管理阶段 → 最近变化 → 团队 → 下个服务节点。健康顺序：年度起点 → 当前状态 → 比较与趋势 → 关注 → 背景。健康内容：概览、数据、体检与检查、健康档案；旧短标签作为兼容显示保留。
计划以目标、当前计划、行动、复查、结果串联。服务先显示正在进行，再目录与历史。历程把已完成事实放回日期上下文；完整依据保留展开。
次级信息：全量比较、来源、报告原文、档案、个人设置。不得出现技术对象名。

## Manager

核心问题：谁需要我、为什么、何时、下一步。

一级：今日 / 成员 / 医疗协同 / 服务 / 更多。
今日只有一个统一责任队列；选中后显示原因、截止、负责人、上下文、原操作。成员360的五个区域：概览 / 健康 / 管理 / 医疗 / 历程。管理内任务、随访、服务和阶段结果沿当前计划组织，不增加一级模块。
次级信息：依据、完整记录、自动跟进状态。更多只提供支撑能力导引，原风险规则/审计/系统深链跳往管理员，保留兼容。

## Doctor

核心问题：需要判断什么、依据是什么、判断后谁执行。

单页队列，待复核/历史筛选；问题 → 背景 → 关键趋势 → 报告依据 → 用药 → 已采取行动 → 人工结论 → 健管执行。健管看到同一复核的依赖摘要，只读；医生完成后通过原命令产生跟进任务，时间轴投影已完成事件。

## Admin

核心问题：连接和自动化是否正常、哪些需要配置、规则和审计在哪。

集成与数据 / 自动化运营 / 规则与知识 / 系统状态。配置、知识审核、设备适配器、Agent技术Trace、反馈治理、审计和15个兼容工具均保留，技术细节默认展开区内。

## 五分钟演示顺序

成员首页行动 → 健康年度基线与当前曲线 → 持续关注 → 健管今日责任队列 → 成员360 → 医疗复核 → 医生判断 → 回到健管管理计划 → 成员任务/服务 → 阶段结果 → 历程 → 人工确认下一周期。

不需要进入Agent控制台、规则或集成才能讲完主线。季度/年度复盘使用已有周期与结果记录，不伪造不存在的专用模块。


## 会员全周期工作入口

|角色|开始位置|本轮主要操作|结果交接|
|---|---|---|---|
|成员|首页的完善健康档案|12步保存、继续、提交初始问卷；原任务、计划和服务仍可用|提交到健管初评|
|健管|今日工作 / 年度管理|入组、确认初评、制定阶段、保存管理日志并创建下一步、协调复查、会诊拆解、服务关联、阶段复盘|医生问题交医生；执行项明确负责人、日期|
|医生|待我复核 / 正式会诊|先核对依据，再提交本人科室意见、综合结论或确认原处方候选|立即生成健管交接；会诊结论进入待方案拆解|
|管理员|原系统角色|集成、自动化、规则、知识、设备、审计、反馈、兼容工具|维持支撑能力，不替代临床判断|

会员360保留五个区域：概览、健康档案、管理、医疗、历程。管理默认为日志工作上下文；已有记录时新增表单收起，最近记录可展开。原计划/任务/自动跟进及数值阶段结果仍有明确入口。

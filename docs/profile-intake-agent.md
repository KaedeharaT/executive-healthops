# 健康资料导入验收记录

日期：2026-09-27。

## 使用路径

健管从「会员 → Member360 → 健康档案」点击「＋ 导入健康资料」，选择体检报告、健康问卷或历史健康档案并上传。页面直接进入健康管理助手看板，显示资料接收、解析、标准化、档案匹配、健管确认、写入档案六个阶段。

报告复用现有指标标准化及 Observation 写入流程；原生问卷确定性映射到现有 IntakeAssessment；历史资料保留来源、原始日期及逐项依据。自由格式文本使用平台已配置的 AI 服务，返回值和引用必须能在原文核对。知识不能生成会员事实。

本版本采取统一批量确认：自动完成读取、整理、匹配和初评草稿预填；正式测量及档案事实在健管确认后写入。一致资料不重复写入，冲突必须选择采用、保留或暂不确认；暂不确认会建立后续待办。历史用药保留为来源明确的用药记录，不创建处方或自主调整药量。需要医学判断时使用现有 DoctorReview，医生提交后继续原来的导入流程。

Member360 和成员端共用正式事实及已确认资料投影，趋势继续读取现有 Observation。未确认候选不会作为成员正式档案展示。原年度基线、Risk Engine 和原体检后管理流程没有改变。

## 复用与审计

- 使用既有 AgentGoal、AgentPlanStep、AgentApprovalRequest、AgentRunTrace、Tool Registry、Supervisor 和 Scheduler。
- 入口事件 HEALTH_DOCUMENT_UPLOADED；文档、解析批次、候选和来源使用既有模型，无新档案数据库。
- 同会员相同文件按 SHA256 幂等；不同文件相同测量按指标、日期、单位和值核对；重复确认不会再次写入。
- 来源文档、原文依据、提取方法、置信度、确认人、确认时间、目标事实和被替换记录可追溯。
- 医生与异常责任不能通过通用恢复、完成或工具接口绕过。

## 实际验证

全量测试在隔离工作副本执行，避免既有迁移测试覆盖演示数据库：

- Baseline：682 passed / 0 failed。
- 全量回归：703 passed / 0 failed。
- 最后完成的错误提示、来源审计和输入边界调整：31 项定向回归通过。

Chromium 从普通角色首页点击进入，使用独立的合成演示数据库验证：

1. 体检文本上传、解析、批量确认、三条新测量入库、报告与趋势同步。
2. 原生问卷上传、初评草稿预填、来源确认与健康档案同步。
3. 历史档案上传、病史/用药/手术记录、吸烟冲突暂缓及后续待办。
4. 资料提交医生、医生页面查看原文、提交判断、原导入流程恢复并确认完成。
5. 不同文件包含相同测量时，第二次新增测量为零。
6. 今日工作直接进入待确认导入；成员端仍只看到已确认资料。
7. 损坏 PDF 安全升级人工处理，原文件可下载并保留重试及人工补充入口。
8. 现用 8501 页面从普通会员路径可见上传入口及三种资料类型。

另在独立数据库使用当前真实 AI 服务解析合成自由格式问卷，得到三项有逐字依据的自述（吸烟、运动、睡眠），流程正常停在 WAITING_MANAGER。

截图见 [profile-intake-agent](images/profile-intake-agent/)，包含三类资料、确认、冲突、真实运行状态、医生返回、成员同步、导入历史及安全失败处理，共 22 张。

## 当前边界

含文字的 PDF、Word、表格及文本复用现有读取能力，原生问卷使用结构化字段映射。图片和无文字层扫描件可以保存，但当前未配置可可靠使用的识别路径，转人工处理，不声称已经识别。服务不可用、文件损坏或结果无法从原文核实时同样保留原文件；不会猜测缺失内容。

没有生成新诊断、处方或 LLM 风险等级。导入已确认测量后，正式风险仍只通过现有确定性规则产生。

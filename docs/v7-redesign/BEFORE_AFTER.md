## 可复核的统计口径

- 比较同一合成数据的 14 个页面/状态，Chromium `151.0.7922.34`，`1440 × 900`。Baseline 从备份提交导出到隔离源码目录，未使用改后代码冒充 Before。
- 可点击控件 **248 → 205**；可见按钮 **93 → 49**，减少 **44**。按钮按 HTML button 的 button/submit 类型统计。
- 包括侧栏、可见筛选、表格选择入口和展开入口；排除闭合展开区、透明悬浮工具栏、隐藏内容和标题锚点。不是源码中 button 调用的数量，也不把移入次级入口的能力称为删除。
- 主页强主 CTA 最大 **1**。0 个是表格行直接选择、暂无人工动作等合理情况。运行中、例外处理和医生判断的实际故事截图另行补充。
- 原始逐控件记录：[Before inventory](../images/v7-redesign/before/inventory.json)、[After inventory](../images/v7-redesign/after/inventory.json)、[汇总](../images/v7-redesign/metrics.json)。
- 最终展示图 04/05/06/13 使用真实运行、已提交、处理例外、待医生判断的故事状态；它们不是用于计算静态减量的空状态。不要把业务记录数量变化算成 UI 简化。
- 常规导航最大 **3** 层，八条主路径平均 **2.13** 层：菜单所对应的工作台计第一层、Member360 或直接事项计第二层、会员内具体处理表单计第三层。页内 Tab、筛选和表单字段不是新页面层级；该数字不等于鼠标点击次数。

## 真实 Chromium 主线

`scripts/qa_v7_workspaces.py` 验证四角色及主要页面；`qa_v7_story.py`、`qa_v7_medical.py`、`qa_v7_intake.py` 使用公开 UI 点击。辅助脚本只使用隔离 QA 端口；未通过内部 URL 打开详情。

已实际走通：

1. Today 选择 Demo Executive A 的阶段复盘 → 同一会员管理页 → 确认并进入下一阶段 → 系统建立首个事项 → 填写结果并完成。
2. 管理工作区申请服务 → 审核 → 预约 → 开始执行 → 记录结果和依据 → 自动出现结果复核事项 → 健管确认；年度与服务入口仍绑定同一会员、同一年度。
3. 阶段复盘提出明确医学问题 → 等待医生 → 医生在两栏判断页面提交 → 后续事项返回 Today。未跳过医生边界。
4. 合成问卷 JSON + 体检 TXT + 自由文本 DOCX：真实进度 **0 → 14 → 29 → 43 → 71%**；本地 AI 真实请求期间保持 **29%**，文件次级进度 **2/3**；等待健管时停止旋转。
5. 例外队列逐项确认和补充 → 一次提交 → **100%**；10 项自动预填，6 项人工补充，未知的可选资料仍未知。没有重新走完 11 张表，没有知识库补会员事实。

运行时计时仅显示耗时，不驱动百分比。保留实际失败、超时、重试、人工接手与医学确认规则。无新增 LLM、Agent 或健康档案模型。耗时 I/O 的事务规则继续执行 [DEVELOPMENT.md](../DEVELOPMENT.md)。
